## Figure, control, metric, and unit inventory

Figures in `experiment.m`:

1. Baseline state trace: state ID versus observation/event step.
2. Baseline transition evidence: legal edge, guard, and postcondition Boolean facts.
3. Readiness sweep: READY qualification step versus readiness confirmations; STANDBY observation counts are retained as printed and asserted metrics, not a second plotted series.
4. Recovery sweep: FAULT exit step versus recovery confirmations; FAULT observation counts are retained as printed and asserted metrics, not a second plotted series.
5. Broken arbitration: strict target, broken target, and observed state for the simultaneous fault/reset input.

Negative cases and cancellation/timeout rollback do not create additional figures. Their transition and
three-row rollback facts are retained in source assertions and model outputs; no MATLAB-rendered view is
claimed without runtime execution.

Interactive controls in `interactive.m`:

- readiness confirmations, integer count 1–4;
- recovery confirmations, integer count 1–4;
- P09 startup proof, Boolean;
- P09 safe-off proof, Boolean;
- scenario mode, enumerated choice;
- interruption event, enumerated choice;
- arbitration policy, enumerated choice;
- reset-to-baseline action.

Retained metrics include state IDs, source/requested/observed state traces,
state observation counts, state changes, readiness and recovery evidence counts,
qualification steps, legal-edge/guard/postcondition/pass evidence, raw input
counts and conflicts, transition/rollback violation counts, priority violations,
false approval, rollback completion, failure modes, and terminal status.

Units are explicit: observation/event step is dimensionless `(-)`, state ID is
dimensionless `(-)`, confirmations and observations are counts, and transition
evidence is Boolean `(-)`. P10 defines no sample period, elapsed deadline,
latency, or jitter unit; those remain P11 concerns.

I/O, hardware I/O, dynamic event list, Simulink dependency, opaque solver, or

data write or destructive migration was performed.

## Independent system-risk review repair

- **Medium — launch-path tutor protocol:** `lesson.m` emitted a prediction and then invoked `experiment.m`,
  which emitted a second prediction before the baseline. The experiment also ran `clc`, erasing the read and
  prediction context from the command window. This violated the one-prediction tutor contract on the actual
  public launch path even though the prior test inspected only `lesson.m`.
- **Repair:** `experiment.m` now owns the single prediction for both direct and launched runs, and it no longer
  clears the learner's read context. The added launch-path behavioral test composes both scripts, requires one
  pre-baseline prediction, and rejects command-window clearing.
- **Medium — first-causal diagnostic masking:** with broken last-request-wins arbitration and missing P09
  safe-off proof together, step 7 violated priority first and step 13 failed the safe-off guard, but
  `failureMode` reported only the later proof failure because final false approval was prevented.
- **Repair:** factual failure classification now keys on an observed priority violation rather than final false
  approval. The independent oracle and retained MATLAB checks exercise strict and broken arbitration with the
  same downstream proof failure, require first violation step 7 for the broken trace, retain both violations,
  and keep `fault-priority-bypassed` as the factual diagnosis.
- **Low — retained figure overstatement:** the original inventory listed seven figures and described series
  that `experiment.m` does not plot. The inventory now lists the five declared figures and distinguishes
  asserted/printed negative-case and rollback outputs from MATLAB-rendered views.
- **Scope:** repairs remain in P10-owned module, focused-test, and retained-evidence paths. Public arguments,
  output names and shapes, manifest lifecycle, P09, shared launchers, and forbidden control/architecture files
  are unchanged.
