# P07 implementation evidence — 2026-08-23

## Result and claim boundary

P07 supplies a complete deterministic source lesson for tracing one rotary-position observation from P05's
hardware-owned `Observe position` function through sensor voltage, ADC count, engineering-unit calibration,
sample quality, and a P07-local qualified-control intake. Static inspection and an independently written Python
oracle establish artifact structure, bounded conversion equations, reachability, quantization limits,
freshness qualification, acquisition-entry guards, malformed-input expectations, rollback compatibility, and
source-level learner flow. P06's existing lesson accepts only scalar `observedAngleDeg`; P07 preserves that
interface by exposing the scalar only when its local value-plus-quality result is eligible.

Evidence classification: **Static**. The Python oracle executes a separate implementation of the documented
formula and path rules on the host. That is executable formula-contract evidence, not execution of `model.m`,
MATLAB numerical fidelity, MATLAB runtime evidence, UI behavior, interface protocol evidence, or physical
validation. The repository source describes an instructional simulated model; no MATLAB, sensor, ADC, device,
bench, or HIL execution is implied.

The manifest lifecycle rule is enforced by validating an isolated promoted candidate before changing the real
P07 lifecycle fields. The exact candidate and final repository results are retained below.

## Changed invariants

- P07 traces five fixed stages from hardware observation to its local qualified-control intake and exactly four
  adjacent ownership handoffs.
- The sensor maps -180 to +180 deg onto 0.5 to 4.5 V; values outside that sensor envelope clip and carry invalid
  saturation quality rather than disappear.
- ADC code is integer and bounded by `2^bits - 1`; calibration is the visible inverse mapping; non-saturated
  quantization residual stays inside one-half LSB.
- Baseline lineage is 30 deg truth reference, 2.833333 V, 2389/4095 count, and approximately 30.021978 deg at
  calibration, qualification, local endpoint receipt, and the eligible scalar P06 adapter output.
- Reached stages form an empty or contiguous prefix. Cancellation and timeout prevent entry; cancellation wins
  their modeled tie. These are already-asserted guards with no timing behavior.
- Invalid data may reach the P07 endpoint with its quality flag false. Factual usability and P06 input
  eligibility require receipt and valid quality; value-only evidence can create false usability without
  changing path, quality truth, or the scalar-input gate.
- Freshness equality passes. Supplied age changes quality only, not ADC count, calibrated value, or reachability.
  Freshness is false with a `NaN` margin until qualification is actually reached.

## Independent audits and repairs

Two bounded read-only audits were run with the primary agent retaining integration ownership. Their initial
reviews anchored the lesson to the inherited rotary angle and P05 observation owner; separated volts, counts,
degrees, milliseconds, and Booleans; selected resolution and supplied-age sweeps; added an empty-prefix entry
guard; distinguished missing from received-invalid data; and prevented P08, P11, or P20 scope from being
consumed. The focused oracle also corrected two initially brittle static expectations so line wrapping and
metric unit formatting could not masquerade as product failures.

The final acceptance audit found that an early draft incorrectly described P06 as receiving value plus
validity, although P06 actually accepts only scalar `observedAngleDeg`. The repair renamed the fifth stage as a
P07-local qualified-control intake, added `p06InputEligible` and a gated scalar adapter output, bound the actual
P06 prerequisite interface in durable tests, and added saturation-plus-value-only isolation cases. The final
numerical audit found freshness was calculated before qualification and lower saturation was under-tested. The
repair gated freshness evaluation on stage 4 and added lower just-outside, lower bounded-extreme, malformed
lower-bound, and discriminating MATLAB-rounding oracle checks. Both audit findings were repaired without
changing P06, P08, P11, P20, or another forbidden path.

## Independent system-risk review repair

- Finding: the rollback fixture proved that persisted `current = P07` recovered to P06, but it never exercised a
  learner who had already completed P07. In that state, rolling P07 back to `scaffolded` left the CLI reporting
  one completion and marking P07 with a completion checkmark, contradicting the available implementation
  frontier and the declared `scaffolded -> implemented -> learner-completed` lifecycle.
- Repair: `bin/learn.py` now derives both the displayed completion marker and completion count from the
  intersection of persisted truthy completion records and currently implemented modules. It does not delete
  completion or note data, so rollback is non-destructive and a later compatible reimplementation may recover
  that learner history.
- Behavioral test: an isolated fixture persists P07 as current and complete with a note, rolls P07 and every
  later module back, resumes to P06, and requires `status` to report six implemented and zero completed while
  `list` shows scaffolded P07 as unavailable. It then proves the P07 completion and note remain on disk.
- Scope: the repair changes only allowed `bin/learn.py`, the P07 durable test, and this retained evidence. It
  does not change the measurement model, P06 interface, manifest lifecycle fields, real learner state, or the
  operator-managed active-batch selector.
